# ADR-022 — application component packages and enforced application/infrastructure import boundaries (2026-10-22)
- Status: Proposed; awaiting owner review of the refactor.
- Decision: organize `autonomous_mixing.application` into responsibility-owned component packages with explicit `__init__.py` interfaces (`__all__`), keep `autonomous_mixing.infrastructure.audio` as one component with its two existing modules, and enforce both with test-only source-import rules. This is a structural refactor: no field, field order, default, validation order, exception type or message, signature, object identity or root export changes, and no behavior is added.
  1. Ownership: `shared` (`results`: `Success`, `PortFailureCode`, `PortFailure`, `PortResult`); `observation` (`contracts`: `AnalysisRequest`, `AnalysisResponse`; `validation`: `validate_analysis_response`; `ports`: `AudioAnalyzer`); `decision` (`contracts`: `DecisionRequest`, `DecisionResponse`; `validation`: `validate_decision_response`; `ports`: `DecisionController`); `admission` (`policy`: `TrackGainPermission`, `ActionAdmissionPolicy`; `contracts`: `ActionAdmissionRequest`, `AdmissionRejectionCode`, `AdmittedAction`, `RejectedAction`, `AdmissionResult`; `admission`: `admit_action`); `execution` (`identity`: `ExecutionWorkspace`, `CandidateIdentity`; `requests`: `StemBinding`, `ExecutionRequest`; `processing`: `ProcessingPlan`, `ArtifactProcessingEvidence`, `ProcessedCandidate`, `ProcessingFailure`, `ProcessingOutcome`; `validation`: `validate_processed_candidate`; `preflight`: `PreflightCode`, `PreflightRejected`, `MetadataReady`, `PreflightResult`, `preflight_execution`; `ports`: `AudioProcessor`). Private helpers stay with their owner (`_gain_permission_for` with `admit_action`, `_check_output` with `validate_processed_candidate`, `_dimensions` with `preflight_execution`, the directory-token pattern with `ExecutionWorkspace`). Execution identities have their own module so that request and processing records do not import each other.
  2. Allowed application dependencies: shared → none; observation → shared; decision → shared; admission → decision; execution → decision, admission. All components may use the standard library and public domain component interfaces (ADR-017). Cross-component imports target the destination package interface, never its internal modules; inside a component, modules import siblings directly, never their own initializer. No application module imports infrastructure, M0 audio, CLI, presentation or third-party code. `decision` keeps its own private copy of the unique-observation check (same check and messages) instead of depending on `observation`; shared stays limited to generic port results.
  3. Processing records and the processor port remain in `execution`, because they serve the same execution operation. A separate processing component is deferred until an independent consumer or dependency requires it.
  4. Compatibility: the application root (all 33 previous exports, same order) and the legacy modules `contracts`, `results`, `execution_contracts`, `execution_preflight` and `ports` (`ports.analysis`, `ports.decision`, `ports.processing`) remain as re-export-only facades of the same objects, without definitions. They may import component interfaces only for re-exporting; component code never imports them. The flat `application/admission.py` is replaced by the `application.admission` package at the same dotted path. Facades keep each old module's own public definitions and aliases, not names it merely imported. Module-qualified class paths changed; pickle payload and `__module__` compatibility are not claimed. Only the compatibility test imports the facades. Removing them needs a later explicit task.
  5. Infrastructure source rules: the `infrastructure` initializer stays descriptive and imports nothing; `audio/__init__.py` re-exports the six existing names from `dsp` and `verification`; `dsp` imports only the standard library and NumPy; `verification` imports only the standard library, NumPy, soundfile and the `domain.project` interface. Neither imports the application, the other leaf, M0 audio, CLI, presentation or provider code. These are source-import rules: the `audio` facade loads both leaves, so no runtime isolation of a leaf is claimed. A future adapter that implements an application port must have its allowed imports and filesystem dependencies designed explicitly; this ADR preauthorizes no infrastructure-to-application import.
  6. Enforcement is test-only. `tests/unit/test_application_infrastructure_boundaries.py` resolves absolute, relative, from-package and aliased imports against the real source tree, matches exact package segments, rejects look-alike packages, unresolved and unclassified modules, checks the matrix, public-interface access, the facade exceptions, facade contents and the infrastructure rules, checks the real component and module graphs for cycles, and imports every module in fresh processes in several orders. `tests/unit/test_application_component_compatibility.py` checks the identity of every migrated definition, alias and protocol at its canonical interface, owner module and each old path, and compares constructor, function and protocol signatures with the 218c3dc baseline.
- Source: owner-approved application/infrastructure component design and implementation plan (2026-10-22), kept in the owner's planning workspace.
- Rationale: the flat application combined observation and decision contracts in one module and split execution ownership across global ports and contract modules. Responsibility-owned components with explicit interfaces and an enforced, acyclic dependency direction follow the domain precedent (ADR-017) and make ownership and coupling visible (QR-07 maintainability, ADR-006 traceability). The infrastructure modules were already separated by concern; explicit rules close the earlier gap that no test enforced their imports, without adding structure.
- Consequences:
  - ADR-016, ADR-018, ADR-020 and ADR-021 keep their meaning; their module names now refer to component packages.
  - Tests that patch or inspect implementation globals must target the owning modules (for example `application.admission.admission`), since a re-export facade does not proxy implementation globals.
  - The fresh-process import checks add a few seconds to the test suite.
  - Unchanged and still open: location resolution, workspace allocation, WAV writing, the processing adapter, the execution service, orchestration; audit findings F2 and F4, and F3's remaining items. No requirement status changes, and no perceptual, source-protection or end-to-end capability follows from the reorganization.
