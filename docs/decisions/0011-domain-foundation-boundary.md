# ADR-011 — dependency-free domain records for projects, context and observations (2026-10-19)
- Status: Proposed; awaiting owner review of the implementing task.
- Decision: add a domain layer `autonomous_mixing.domain` inside the existing package. It contains immutable records for project snapshots, tracks, analysis scopes, audio-artifact metadata, explicitly supplied musical context and observations, with invariants enforced at construction. The layer:
  1. uses only the Python standard library (frozen dataclasses, tuples/frozensets, enums) and its own modules; no NumPy, audio I/O, storage, provider or CLI imports. A test enforces this import boundary;
  2. uses typed opaque identifiers (track identity is independent of display names), explicit units, finite numbers (booleans, NaN, infinity and integers beyond the float range rejected; derived artifact end times and Nyquist frequencies must also be finite floats), zero-offset UTC timestamps, and an explicit `Unavailable(reason)` result instead of zero or missing numbers;
  3. is track-role-agnostic: roles are explicit, sourced assertions in `MusicalContext`; an unknown role is absence and is never derived from names or genres;
  4. treats artifact paths, hashes and sample metadata as metadata only. `AudioArtifact.revision` is the production revision (provenance) and is never retagged. `validate_observation_sources(observation, artifacts, checkpoint, snapshot)` takes an explicit `ArtifactCheckpoint` ([ADR-015](0015-correction-attempt-and-artifact-checkpoint-records.md)). The checkpoint state must match the snapshot's project and revision; every referenced source must be a checkpoint member whose supplied metadata equals the recorded member; production revisions may differ from the state revision. Coverage and Nyquist checks use metadata without resampling or inferring signal alignment. (Amended 2026-10-20 before acceptance: the earlier rule that each source's production revision equals the snapshot revision prevented retaining unchanged artifacts in later states.)
  5. raises `ValueError` for every invalid construction or reference.
- Source: owner-approved mixing-core design (2026-10-19) and its repository adaptation, "replacement Task 1". These planning documents are kept in the owner's planning workspace, not in this repository.
- Rationale: later components (project loading, multitrack measurements, context, run records) need one shared, validated vocabulary that can be tested offline and without the provider SDK (QR-02, QR-07). Keeping the vocabulary dependency-free prevents analysis or storage choices from leaking into it, and role-agnostic records follow ADR-006.
- Consequences:
  - Groundwork only for FR-01/02, FR-03/04, FR-11, FR-12 and QR-03/08; none of these requirements is met by this layer, and the M0 audio code, CLI and `m0.1` report are not changed or integrated.
  - Problem candidates and uncertainty (FR-05, D11), constraint and preference types (D6), actions, decisions, validation and run records are not defined here; they need their own reviewed tasks.
  - A non-empty unit string does not establish compatibility with a metric catalog. Artifact coverage uses exact float comparisons with no tolerance (alignment tolerance is D3). Content hashes must be lowercase SHA-256 hex.
  - Existing M0 modules are not required to adopt the domain layer until a reviewed migration task.
